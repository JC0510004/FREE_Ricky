3. Diagrama de Secuencia - Autenticación

sequenceDiagram
    actor U as Usuario
    participant FE as Frontend
    participant BE as Backend Django
    participant DB as MySQL
    participant CA as Redis

    rect rgb(15,67,111)
    Note over U,CA: FLUJO DE LOGIN
    end

    U->>FE: 1. Ingresa usuario + contrasena
    FE->>BE: 2. POST /api/login/

    BE->>CA: 3. Verificar rate limit 5/min
    alt Rate limit excedido
        CA-->>BE: Limite alcanzado
        BE-->>FE: 429 Too Many Requests
        FE-->>U: Demasiados intentos
    end

    BE->>DB: 4. SELECT usuario WHERE username = ?
    alt Usuario no existe
        DB-->>BE: Sin resultados
        BE->>BE: 5. dummy_check_password proteccion timing
        BE-->>FE: 401 Credenciales invalidas
    end

    DB-->>BE: Usuario encontrado
    BE->>BE: 6. check_password con Argon2

    alt Contrasena incorrecta
        BE->>DB: 7. Incrementar failed_attempts
        alt failed_attempts >= 5
            BE->>DB: 8. Bloquear cuenta 15-1440 min
            DB-->>BE: Cuenta bloqueada
        end
        BE-->>FE: 401 Credenciales invalidas
    end

    BE->>DB: 9. Reset failed_attempts update last_login
    BE->>BE: 10. Generar JWT access + refresh
    BE->>FE: 11. 200 access_token user
    FE->>FE: 12. access_token en memoria NO localStorage
    FE->>U: 13. Login exitoso

    rect rgb(15,67,111)
    Note over U,CA: PETICION AUTENTICADA
    end

    U->>FE: 14. Navega a /home
    FE->>BE: 15. GET /api/partidas/ + Bearer token
    BE->>BE: 16. Verificar JWT HS256

    alt Token expirado 15 min
        BE-->>FE: 17. 401 Token expired
        FE->>BE: 18. POST /api/token/refresh/ cookie HttpOnly
        BE->>DB: 19. Validar refresh token
        DB-->>BE: Token valido
        BE->>BE: 20. Generar nuevo access token
        BE->>FE: 21. 200 new_access_token
        FE->>BE: 22. Retry peticion original con nuevo token
    end

    BE->>DB: 23. SELECT partidas WHERE usuario_id = ?
    DB-->>BE: Lista de partidas
    BE->>FE: 24. 200 lista partidas
    FE->>U: 25. Muestra partidas

5. Diagrama de Flujo - Recuperación de Contraseña

flowchart TD
    A[Usuario olvida contrasena] --> B[Ingresa email]
    B --> C[POST /api/password-reset/]
    C --> D{Email existe?}
    D -->|No| E[Mensaje generico: Email enviado]
    D -->|Si| F[Generar token UUID + codigo]
    F --> G[Guardar SHA-256 en BD]
    G --> H[Enviar email con codigo + enlace]
    H --> I[Usuario recibe email]
    I --> J[Clic en enlace]
    J --> K[GET password-reset/confirmar/]
    K --> L{Token valido?}
    L -->|No| M[Error: Token invalido]
    L -->|Si| N[Marcar confirmado=True]
    N --> O[GET password-reset/verificar/]
    O --> P{Confirmado?}
    P -->|No| Q[Error: No confirmado]
    P -->|Si| R[Formulario nueva contrasena]
    R --> S[Ingresa codigo + nueva contrasena]
    S --> T[POST password-reset/verificar-codigo/]
    T --> U{Codigo valido?}
    U -->|No| V[Error: Codigo incorrecto]
    U -->|Si| W[POST password-reset/confirm/]
    W --> X{Token expirado? 15 min}
    X -->|Si| Y[Error: Token expirado]
    X -->|No| Z[Actualizar contrasena Argon2]
    Z --> AA[Eliminar token usado]
    AA --> AB[Redirigir a /login]
    AB --> AC[Ingresa nueva contrasena]
